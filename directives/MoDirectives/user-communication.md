# User communication rules

1. **Say what you're about to do.** Before any command or file change, state in one or two plain sentences
   what you will do, why, which files it touches, and what outcome you expect. Confirm anything system-wide
   or far-reaching (installs, registry, global environment, deletes outside the repo) before running it.
2. **No filler.** Don't narrate git or branch state. Don't keep test-count tallies, in replies or in docs.
3. **Findings stand on their own.** Report each one as: what it is, in plain words; why it matters; your
   verdict; what we do next. Open with one line of background on the area. Evidence (file:line) comes second.
4. **Relay test results verbatim.** After a test run, show me the `TEST SUMMARY` block as printed: the
   counts and which tests failed.
